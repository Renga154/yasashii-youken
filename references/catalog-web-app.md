情報をしまっておき、人がログインして使うアプリ(記録・管理・予約・会員制など)を作るときに、`catalog-common.md` と一緒に読む。「当てはまる条件」の番号は catalog-common と同じ(SKILL.md の5条件)。「重さ: 聞く」は候補で、絞り方は SKILL.md のステップ2に従う。
catalog-common と重なる項目: W1 は C2、W6 は C7、W11 のお金の部分は C3 と同じ判断。共通の答えがあれば聞き直さず、その答えから選んで記録する。
完成チェック例で「AI が先に確かめる」としたもののうち、テスト用の別アカウントや管理者でない利用者で確かめるものは、spec-template のとおり AI だけの [x] の行にし、本人には頼まない。

## W0. 開いたときの画面と、いちばんよく使う流れ
- **重さ**: 聞く(画面のあるアプリなら毎回。ステップ1の完成イメージから2〜3案の画面イメージを描いて「どれが近い?」と聞く。描き方は question-style.md の「見本の出し方」)
- **当てはまる条件**: ②③
- **本人への聞き方**: 「アプリを開いたとき、最初に何が見えるとうれしいですか? いちばん近い画面を選んでください」
- **選択肢**(分野に合わせて言い換える。例は家計簿):
  - A. すぐ入力できる画面 — 見え方: 開くと大きな[+記録する]ボタン。今月の合計は上に小さく / お金: 0円 / 注意: 種類ごとのまとめを見るには別の画面に移る / 後から変える: ◎
  - B. まとめが先 — 見え方: 今月の合計と種類ごとのグラフが上、記録の一覧がその下 / お金: 0円 / 注意: 記録するたびに、入力画面を開く手間が1回増える / 後から変える: ◎
  - C. カレンダー — 見え方: 日ごとの金額(予約なら空き)がカレンダーに並び、日付を押すと中身が出る / お金: 0円 / 注意: 細かい一覧は見にくい / 後から変える: ◎
  - おまかせ → ステップ1の完成イメージで最初に出てくる動作が中心の案(「記録できたら」なら A、「いくら使ったか分かったら」なら B、予約なら C)
- **AI向けメモ**: 選ばれた画面イメージを youken.md の「見本」に貼る。画面に描いた要素(グラフ・検索・合計など)はすべて「できること」に書き、描かなかったがこの分野で多くの人が期待しそうなもの(グラフ、自動取り込み、通知など)は「やらないこと」に書く。お客さん用と管理用で画面が分かれるなら、お客さん側を見本にし、管理側は W10 で決める。合計やグラフを描いたら W13 は B で記録する。
- **完成チェック例**: 「ホーム画面のアイコン(または URL)から開くと、要件書の見本と同じ並び(例: 一番上に今月の合計、その下に[+記録する])の画面が出る」

## W1. 使える人の入り方(誰でも登録できるか、招待した人だけか)
- **重さ**: 聞く(C2 かステップ1の「誰が使う?」で決まれば、聞かずに記録)
- **当てはまる条件**: ②③④
- **本人への聞き方**: 「このアプリ、知らない人が自分で登録して使い始めてもいいですか? それとも、あなたが招待した人だけが使えるようにしたいですか?」
- **選択肢**:
  - A. 自分だけ — 見え方: あなた1人だけがログインして使う / お金: 0円 / 注意: あとで家族やスタッフを入れるとき、「誰が何を見られるか」を作り足す必要がある / 後から変える: △
  - B. 招待した人だけ(家族・スタッフ・会員) — 見え方: あなたが招待した人だけが入れる。「新規登録」ボタンは出ない / お金: 0円 / 注意: 招待のリンクが転送されると別の人が入れてしまうので、期限付き・1回だけ使えるリンクにする / 後から変える: △ 自分だけに戻すのは簡単。誰でも登録できる形にするなら、迷惑な登録への備えと利用規約のページを足す
  - C. 誰でも登録できる(お客さん・一般の人向け) — 見え方: 入口に「新規登録」ボタン。誰でもすぐ使い始められる / お金: 0円〜(使う人が増えると月数千円かかることがある) / 注意: いたずら登録や迷惑な書き込みへの備えと、利用規約・個人情報の扱いのページが要る / 後から変える: △
  - おまかせ → B。知らない人が入れず安全で、閉じた形から広げる方が、広く出してから閉じるより安全なため
- **AI向けメモ**: A(自分だけ)でも新規登録は止め、本人のメールアドレスだけを許可する(Google ログインでも同じ)。Supabase なら新規サインアップを無効にし、招待はサーバー側の `auth.admin.inviteUserByEmail` で送る。招待メールを送るには W3 と同じ送り元の設定が要るので、家族やスタッフだけで Google ログインなら、招待メールは送らず「許可するメールアドレスの一覧」で入れる(送り元の住所代がかからない)。完成チェック用のテストアカウントは確認後に削除し、許可の一覧から外す。C ではボット対策(Turnstile など)・メール確認・回数制限・通報と利用停止を用意する。利用者同士でメッセージを送り合う機能(DM・チャット)を付けると「他人の通信の媒介」になり、電気通信事業の登録または届出が要りうる(自社の商品・サービスの販売や問い合わせ受付だけなら非電気通信事業)。DM の要望が出たら1問で確かめ、要確認として扱う。外部送信規律(2023-06-16施行): SNS・掲示板・情報配信型のサービスで解析タグや広告タグを入れるなら、送る情報・送り先・目的の公表などが要る。会員向けに動画・記事・オンライン講座などの中身そのものを配信するサービスも、利用者が少なくても対象になる(総務省 FAQ 問2-8・問1-11)。自分の店の予約・会員管理だけなら対象外の見込み(詳しくは C6 メモ)。出典: https://www.soumu.go.jp/main_content/000477428.pdf , https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu_00002.html (確認 2026-10-02)
- **完成チェック例**: 「招待していないメールアドレス(または Google アカウント)で入ろうとすると、中身は見えず『招待された人だけが使えます』と出る」(AI が先にテスト用のアカウントで確かめる)

## W2. 誰が何を見られる・変えられるか
- **重さ**: 条件次第(使う人が2人以上のときだけ聞く。自分だけなら「自分の記録は自分だけ」と決めて記録)
- **当てはまる条件**: ②④⑤
- **本人への聞き方**: 「もしAさんの記録がBさんに見えてしまったら困りますか? 記録を直したり消したりしていいのは誰ですか?」
- **選択肢**:
  - A. 自分の記録は自分だけ(管理者のあなたは全員分を見られる) — 見え方: 利用者の一覧には自分の予約・記録だけが出る / お金: 0円 / 注意: スタッフにも見せたくなったら、見られる人を足す作業が要る / 後から変える: △
  - B. グループの中は全員が見られて書ける(家族・チーム) — 見え方: 同じグループの人は同じ一覧を見て、誰でも追加・修正できる / お金: 0円 / 注意: 誰かがうっかり消すことがある。消す前の確認と、消したものを一定期間戻せる仕組みを付ける / 後から変える: △
  - C. 見るのは全員、直せるのは書いた本人と管理者 — 見え方: 掲示板や共有カレンダーのような形 / お金: 0円 / 注意: 名前や連絡先など、全員に見せてよい項目かを1つずつ確かめる必要がある / 後から変える: △
  - D. リンクを知っている人なら誰でも見られる(ログインなし) — 見え方: 1件ごとに「共有リンク」を作って送れる / お金: 0円 / 注意: リンクが転送されると広がる。個人情報には使わない / 後から変える: ◎
  - おまかせ → A。いちばん漏れにくく、見られる範囲は後から広げる方が安全なため
- **AI向けメモ**: 権限はサーバー側(データベースの行単位の制限)で守る。ボタンを隠すだけでは守れない。AI が作ったアプリで他人のデータが丸見えになる事故は実際に起きている(Lovable の CVE-2025-48757: RLS が不十分で、未ログインの第三者が任意のテーブルを読み書きできた。調べた1,645件のうち170件で氏名・メール・金銭情報・APIキーが露出)。Supabase の場合: 公開スキーマの全テーブルで RLS を有効にし `auth.uid()` 基準のポリシーを書く/不要な `anon` の権限は revoke する(ポリシーを足しても既定の grant は消えない)/Storage にも同じ制限/`service_role` キーをブラウザに置かない/Security Advisor で確認。完成前に、AI が anon キーで直接 API を呼び、他人の行が返らないことを確かめる。漏えいしたときの報告義務と、小さな事業やサークルも個人情報保護法の対象になる点は C6 メモ。出典: https://mattpalmer.io/posts/2025/05/CVE-2025-48757/ , https://supabase.com/docs/guides/database/postgres/row-level-security (確認 2026-10-02)
- **完成チェック例**: 「テスト用の利用者AとBを用意し、Aで記録を1件作る。Bでログインすると、一覧・検索・Aの記録のURLを直接開く、のどれでもAの記録が見えない。ログアウトした状態でも見えない」(AI が先に確かめる)

## W3. ログインの仕方
- **重さ**: 条件次第(自分以外の人もログインするなら聞く。自分だけなら、本人がやる設定がいちばん少ない方に決めて記録する: 保存先の画面でスイッチを入れるだけで Google ログインが使えるなら A。Google Cloud で同意画面と OAuth クライアントを本人が作る必要があり、ステップ1で設定は「一緒に見ながら」と答えていたら B(自分宛てだけなので0円)。Google を使っていないと分かっていれば B)
- **当てはまる条件**: ②④
- **本人への聞き方**: 「使う人は、ふだんGoogle(Gmail)のアカウントを持っていそうですか? LINEのほうがなじみがありますか? それともメールアドレスくらいですか?」
- **選択肢**:
  - A. Googleでログイン — 見え方: 「Googleで続ける」を押して、自分のアカウントを選ぶだけ / お金: 0円 / 注意: Googleアカウントを持っていない人は使えない / 後から変える: ◎
  - B. メールに届くリンクで入る(パスワードなし) — 見え方: メールアドレスを入れると、ログイン用のボタン付きメールが届く / お金: 自分宛てだけなら0円。家族など自分以外にも送るなら、送り元にする自分専用の住所(○○.com など)が要り、年約1,700円(2026-10時点の目安) / 注意: メールが迷惑メールフォルダに入ることがある。ログインのたびにメールを開く手間 / 後から変える: ◎
  - C. メールアドレスとパスワード — 見え方: よくある形。最初に登録し、次からは入力して入る / お金: B と同じ(「パスワードを忘れた」のメールを送るため) / 注意: よそで使い回したパスワードが漏れると入られるおそれ / 後から変える: ◎
  - D. LINEでログイン — 見え方: 「LINEでログイン」を押し、LINEアプリで許可する / お金: 0円 / 注意: 標準ではメールアドレスが取れないので、メールで知らせる仕組みと組み合わせにくい / 後から変える: ◎
  - おまかせ → 自分だけ・家族だけなら A。Google を使わない人がいそうなとき(お客さん向けなど)は A+B(Google のボタンとメールのリンクを両方置く)。どちらもパスワードを覚えなくてよいため
- **AI向けメモ**: Supabase Auth は Google・マジックリンク・パスワードとも追加料金なし(月間利用者数で課金)。Supabase 標準のメール送信は1時間2通・チームメンバー宛てだけで、本番には使えない。マジックリンク・パスワード再設定・招待を使うなら独自の SMTP を設定する(例: Resend 無料3,000通/月・100通/日、Pro 20ドル≈3,200円/月で50,000通)。Resend の resend.dev の送り元からはアカウント本人のアドレスにしか送れないので、自分以外に送るなら本人名義(仕事なら会社の名義)の独自ドメインを確認して使う(料金は C8 メモ)。送信ドメインに SPF/DKIM を設定して迷惑メール判定を減らす。Supabase の Google ログインは、本人の Google Cloud で同意画面(アプリ名・プライバシーポリシーの URL)と OAuth クライアントを作る作業が要るので、youken.md の「あなたにやってもらうこと」に書く(Firebase Authentication は画面で Google を有効にするだけ)。LINE ログインは無料。ストアのアプリで Google・LINE などの外部ログインを主に使うなら、Apple ガイドライン4.8により、名前とメールだけを集めメールを隠せる別のログイン(Appleでサインインなど)も用意する。出典: https://supabase.com/docs/guides/auth/auth-smtp , https://supabase.com/docs/guides/auth/social-login/auth-google , https://firebase.google.com/docs/auth/web/google-signin , https://resend.com/pricing , https://resend.com/docs/knowledge-base/403-error-resend-dev-domain , https://developers.line.biz/ja/docs/line-login/overview/ , https://developer.apple.com/jp/app-store/review/guidelines/ (確認 2026-10-02)
- **完成チェック例**: 「ログイン画面でメールアドレスを入れて送ると、1分以内にメールが届き(迷惑メールフォルダも確認)、中のボタンを押すと自分の記録画面が開く」

## W4. スマホでの使い方(URLで開く/ホーム画面に置く/ストアのアプリ)
- **重さ**: 聞く(ステップ1の完成イメージや「あなた自身は?」の答えで、ストアに出すかどうかがはっきりしていれば聞かずに記録)
- **当てはまる条件**: ①②③
- **本人への聞き方**: 「『アプリ』と聞いて、App Store や Google Play から入れるものを思い浮かべていましたか? 使う人に URL を送って開いてもらう形でもよいですか?」
- **選択肢**:
  - A. URLを開いて使うページ(インターネットを見るアプリで開く) — 見え方: 送られた URL を開いて使う。パソコンでも同じ / お金: 0円 / 注意: iPhone では、この形のままだとスマホの通知を受け取れない / 後から変える: × ストアのアプリにするなら作り直し(ホーム画面に置く形には◎)
  - B. ホーム画面にアイコンを置いて、アプリのように開けるページ — 見え方: 最初に1回「ホーム画面に追加」すると、アイコンから全画面で開ける / お金: 0円 / 注意: iPhone では自動で案内が出ないので、「共有ボタン→ホーム画面に追加」の説明を画面に出す / 後から変える: × ストアのアプリにするなら作り直し(URL を開くだけの形には◎)
  - C. App Store・Google Play のアプリ — 見え方: ストアで探して入れる。スマホの通知が確実に届く。公開と直すたびに審査があり、届くまで数日かかることもある / お金: Apple 年約1万3千円 + Google 最初だけ約4,000円(2026-10時点の目安) / 注意: 個人で登録すると、ストアにあなたの名前が載る(Google Play はメールアドレスも。有料アプリやアプリ内課金で売上が出ると、自宅の住所も公開される) / 後から変える: ×
  - おまかせ → B。0円で審査待ちもなく、直したらすぐ全員に届き、アプリのように使えるため
- **AI向けメモ**: B=PWA(manifest・service worker・アイコン・standalone 表示)。iOS の Web プッシュは iOS/iPadOS 16.4以降、ホーム画面に追加した Web アプリだけで、ボタンを押すなどの操作をきっかけに許可を求める。C の主なルール: Apple ガイドライン4.2(Web サイトを包んだだけのアプリは不可)、5.1.1(v)(アカウントを作れるならアプリ内で削除も)、4.8(外部ログイン時の代わりのログイン)、3.1.1(デジタルの中身の解放は App 内課金)。現実のサービスや物の代金は App 内課金の対象外(3.1.3(e))。日本ではスマホ新法対応で2025-12から代替決済・外部リンク・手数料の仕組みが変わった(iOS 26.2以降)。デジタルの中身を売るなら手数料率を要確認。Google Play はアプリ内と Web の両方にアカウント削除の手段が要る(W9)。Google の個人アカウントは、公開前に12人以上のテスターが14日間続けてテストする必要がある。審査はApple は多くが24時間以内、Google は最大7日ほど。Google Play の個人アカウントは氏名・国・メールアドレスが公開され、収益を得ると詳しい住所も公開される。自宅住所を出したくないなら、収益化しない・組織アカウント(D-U-N-S 番号が要る)にする・Web(PWA)で売る、のどれか。Apple の個人登録は本名が販売者として表示される。Apple の年会費は公式ページでは99ドルの表示で、日本で Web から登録すると12,980円という報告が多い(公式の円表示はないので、登録画面で確かめる)。出典: https://developer.apple.com/jp/programs/enroll/ , https://developer.apple.com/distribute/app-review/ , https://developer.apple.com/support/app-distribution-in-japan/ , https://support.google.com/googleplay/android-developer/answer/6112435?hl=ja , https://support.google.com/googleplay/android-developer/answer/14151465?hl=ja , https://support.google.com/googleplay/android-developer/answer/13628312?hl=ja , https://support.google.com/googleplay/android-developer/answer/9859751?hl=ja , https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/ (確認 2026-10-02)
- **完成チェック例**: 「iPhoneのSafariでURLを開き、共有ボタン→『ホーム画面に追加』を押すと、ホーム画面にアイコンができ、そこから開くとURL欄のない全画面で表示される」

## W5. 記録する項目
- **重さ**: 聞く
- **当てはまる条件**: ③④⑤
- **本人への聞き方**: 「記録する項目は、今の紙やExcelの欄をそのまま使いますか? それとも、よく使う5つほどから始めますか?」(今の紙やExcelがあれば、写真やファイルをあとで送ってもらえるとその欄に合わせます、と一言添える。送ってもらう材料は「あなたにやってもらうこと」に書く)
- **選択肢**:
  - A. 今の紙・Excelの項目をそのまま使う — 見え方: いつもの欄が同じ順に並ぶ / お金: 0円 / 注意: もう使っていない欄まで入力の手間が増える / 後から変える: ◎

- **AI向けメモ**: Supabase Free: 月間利用者50,000人・DB 500MB・ファイル1GB・転送5GB・動かせるプロジェクト2つ・1週間操作がないと一時停止・自動バックアップなし(CLI の `db dump` で定期的に書き出す。C10 メモ)。Pro: 25ドル(≈4,000円)/月、月間利用者100,000人(超過1人0.00325ドル)、ディスク8GB、ファイル100GB、転送250GB、毎日のバックアップを7日分。Firebase: 認証は月間利用者50,000人まで無料、Firestore は1GiB・読み取り5万回/日・書き込み2万回/日まで無料。アプリを置く場所は、仕事用なら商用利用を認める無料の置き場所(Cloudflare Pages など。C8 メモ)にし、Vercel Hobby(非商用・個人利用のみ)は使わない。Vercel を使うなら Pro(開発者1人20ドル≈3,200円/月、税抜)の分を B に足す。B の目安 = Supabase Pro。C3 の上限を超える案は「上限を超えます」と書いたときだけ出す。予算アラートと使用上限を設定し、「上限の80%で知らせる」を決めたことリストに、増えたときの金額を youken.md の「お金」の「増えるとき」に書く。出典: https://supabase.com/pricing , https://supabase.com/docs/guides/platform/backups , https://firebase.google.com/pricing , https://vercel.com/docs/plans/hobby (確認 2026-10-02)
- **完成チェック例**: 「AIが用意した『使用量の確かめ方』の手順どおりに開くと、今月の利用人数と保存している量、無料の上限まであとどのくらいかが分かる」

## W12. 記録を持ち出せるか(Excelで開ける形で書き出す)

- **本人への聞き方**: 「記録をExcelで開いたり、税理士さんや別のサービスに渡したりすることはありそうですか?」

  - B. 利用者も自分の分だけ書き出せる — 見え方: 各自の画面に「自分の記録を書き出す」ボタン / お金: 0円 / 注意: 他の人の分が混ざらないか確かめる必要がある / 後から変える: ◎

## W14. 電波がないところで使うか
- **重さ**: 条件次第(地下・山・倉庫・畑・イベント会場など、電波が弱い場所で記録するなら聞く)
- **当てはまる条件**: ②③
- **本人への聞き方**: 「このアプリを使う場所に、電波が届きにくいところはありますか? そこで記録できないと困りますか?」
- **選択肢**:
  - A. つながっているときだけ使う — 見え方: 電波がないと「送れませんでした」と出る。入力した内容は消えず、つながったら送り直せる / お金: 0円 / 注意: 電波のない場所では新しく記録を残せない / 後から変える: △
  - B. 電波がなくても記録でき、つながったら自動で送る — 見え方: いつでも記録でき、「未送信 2件」のように出る / お金: 0円(作る手間は大きく増える) / 注意: 2人が同じ記録を同時に直すと、どちらかの変更が上書きされることがある / 後から変える: ◎
  - おまかせ → A。作りが単純で不具合が少なく、多くの場合はこれで足りるため
- **AI向けメモ**: A でも入力中の内容は端末に下書き保存し、送信に失敗したら再送ボタンを出す。B は service worker+IndexedDB の送信待ちリスト、updated_at による食い違いの検出(後勝ち/確認)が要り、ストアのアプリの方が確実な場合もある。iPhone の Safari は、Safari を使った日で数えて7日のあいだそのサイトを一度も操作しないと、スクリプトで保存したデータを消す(ホーム画面に追加した Web アプリは自分が使われた日で数えるので、使っていれば消えない)。B を選ぶなら W4 は B 以上にする。出典: https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/ (確認 2026-10-02)
- **完成チェック例**: 「機内モードにして記録を保存すると『送れませんでした』と出て、入力した内容は消えていない。機内モードを切って『送り直す』を押すと一覧に出る」
