# 決めること一覧: ホームページ・LP・ブログ・ポートフォリオ

お店・教室・個人事業の紹介サイト、1枚の宣伝ページ(LP)、ブログ、作品集など「見せることが中心のサイト」を作るときに読む。
項目は大事なもの(後から変えにくい・お金や法律に関わる)から順に並べてある。「重さ: 聞く」は候補で、絞り方は SKILL.md のステップ2に従う。
catalog-common と重なる項目: S2 は C9 と C1、S6 の販売は C7、S12 は C8 と同じ判断。ホームページでは S2・S6・S12 で聞き、C1・C8・C9 は使わない(金額は S12 にそろえる)。C1 の「既製のサービスで作る」は S2 の C として、「予約・支払いなどの部品だけ既製のサービス」は S6 として聞く。S2 の C は、ステップ1で設定の作業を自分でできそうと答え、ふだんパソコンを使う人にだけ出す。
「当てはまる条件」の番号は SKILL.md の5条件: ①お金・抜けにくさ ②使う人が見るもの・できること ③後から変えにくい ④個人情報・セキュリティ ⑤本人の仕事や生活のルール。

## S1. 見た人に最後にしてほしいこと(サイトの目的)
- **重さ**: 聞く(依頼やステップ1の答えで1つに決まれば聞かず、決めたことリストに書く)
- **当てはまる条件**: ②③⑤
- **本人への聞き方**: 「このサイトを見た人に、最後に何をしてほしいですか? いちばん大事なものを1つ選んでください」
- **選択肢**:
  - A. 問い合わせ・相談してほしい — 見え方: どのページにも「お問い合わせ」ボタンがあり、2回押せば送る画面に着く / お金: 0円 / 注意: 届いた問い合わせに返事をする手間が増える / 後から変える: ◎
  - B. 予約してほしい — 見え方: 「予約する」ボタンから空いている日時を選べる(S6) / お金: 予約が月50件までなら0円(S6) / 注意: 受け付ける時間や人数などの決まりを決める必要がある(S6b) / 後から変える: △
  - C. 実績や作品を見て、信頼してほしい(名刺代わり・作品集) — 見え方: 実績・作品の写真・自己紹介・お客様の声が中心。作品は押すと大きく出て説明が読める。連絡は電話やメールのボタン程度 / お金: 0円 / 注意: 情報が古いままだと、かえって不安を与える / 後から変える: ◎
  - D. お店に来てほしい — 見え方: トップに今日の営業時間・定休日、「地図を開く」ボタン、メニューの写真 / お金: 0円 / 注意: 営業時間や臨時休業が古いままだと「来たのに閉まっていた」になる(S2 で直し方を決める) / 後から変える: ◎
  - おまかせ → 来てもらう場所がある仕事なら D(予約も受けるなら D が主、B が副)。作品や実績を見せる仕事なら C。それ以外は A。理由: その仕事のお客さんが取りたい次の一歩に、いちばん近いため
- **AI向けメモ**: 目的=主ボタン(CTA)。ヘッダー・フッター・スマホ下部固定に置く。B や物販なら S6・S11 を「聞く」に上げる。C は実績ページと構造化データ(LocalBusiness / Organization)。作品が中心なら画像最適化(AVIF/WebP・srcset・遅延読み込み)と拡大表示。D は営業時間・定休日を1か所のデータにして、トップ・アクセス・構造化データ(openingHours)で同じものを使う。地図ボタンは Googleマップのお店の情報を開く(S8・S13)。「全部」と答えられたら主1つ+副1つに絞って決めたことリストに書く。
- **完成チェック例**: 「スマホでトップページを開くと、下にスクロールしなくても『○○する』ボタンが見え、押すと○○の画面に進む」

## S2. 文章や写真を変えたいとき、誰がどうやって直すか
- **重さ**: 聞く(C9・C1 の代わり。スマホ中心か、設定の作業ができそうかはステップ1の答えを使い、聞き直さない)
- **当てはまる条件**: ①③⑤
- **本人への聞き方**: 「お知らせ・メニュー・料金などを書き換えたくなるのは、どのくらいの頻度ですか? 今、お知らせや臨時休業を Instagram などに出していますか?」
- **選択肢**:
  - A. AI に頼んで直す — 見え方: 更新画面はなし。パソコンで AI を開いて「料金を3,000円に変えて」と頼むと、数分で変わる(スマホから頼めるかは使っている環境しだい) / お金: 0円 / 注意: 自分だけでは直せない。臨時休業のような急ぎのお知らせも AI との作業が必要 / 後から変える: ◎
  - B. 更新画面(文章や写真を自分で変えられる画面)で自分で直す — 見え方: ブログのような入力画面にログインし、お知らせや写真を自分で足したり直したりできる / お金: 0円(更新画面に使う無料サービスの範囲。直す人は3人まで) / 注意: 作る量が増えるので、自分で直す場所(お知らせ・メニューなど)を先に決める / 後から変える: △
  - C. 画面を見ながら自分で作れるサービス(STUDIO・ペライチ・Wix)で、自分で作って自分で直す — 見え方: 画面を見ながら、指やマウスで動かして直せる。デザインはそのサービスでできる範囲 / お金: 自分の URL で公開するなら、STUDIO は年払いなら月590円・月払いなら月1,290円(2ページまで)、ペライチは月1,628円(月払い)から(税込。2026-10時点の目安) / 注意: 困ったときは自分でそのサービスの使い方を調べることになり、AI が手伝える範囲は狭い / 後から変える: × ほかの案にするならほぼ作り直し
  - D. お知らせは今どおり Instagram などに出し、サイトには変わりにくい情報だけ置く — 見え方: サイトには営業時間・メニュー・地図と「最新のお知らせは Instagram で」のボタン。臨時休業はいつものように Instagram に出す / お金: 0円 / 注意: Instagram を見ない人には臨時休業が伝わらない / 後から変える: ◎
  - おまかせ → お知らせを SNS に出しているなら D。出していなければ、書き換えが月1回より少ないなら A、毎週のようにお知らせを出すなら B。理由: 今の習慣を変えずに済み、どれも0円で後から切り替えやすい
- **AI向けメモ**: A=静的サイト(Astro 等)を Cloudflare Pages に置く(Free: 月500ビルド・1サイト2万ファイル・1ファイル25MiB。https://developers.cloudflare.com/pages/platform/limits/ )。Vercel Hobby は「non-commercial, personal use only」なので店や仕事のサイトには使わない(https://vercel.com/docs/plans/hobby 、2026-09-14更新)。B=microCMS Hobby 月0円(API 5個・メンバー3人・転送量20GB/月で超えると API 停止・コンテンツ1万件)、Team 月4,900円〜(税抜)(https://microcms.io/pricing 2026-10-02確認)。公開用のページを作るとき(ビルド時)に取得すれば転送量はほとんど使わない。更新時は Webhook で再ビルド。値段や営業時間だけなら、Google スプレッドシートを更新画面にしてビルド時に読む方法も軽い。WordPress はエックスサーバー スタンダード 月1,100円(12か月)〜990円(36か月)税込・初期費用0円(https://www.xserver.ne.jp/price/ )で、安全のための定期的な更新作業が要る。Notion 連携は Notion 無料プラン+API でビルド時に取得(Notion Sites で独自ドメインを使うと有料プラン+1ドメイン月$8〜10≒1,300〜1,600円、https://www.notion.com/ja/pricing )。C を出す条件は冒頭のとおり(ステップ1で「パソコン・設定は自分でできそう」)。選ばれたらコードを書かず、そのサービス上で作る手伝いに切り替える(SKILL.md ステップ5の既製のサービスの場合)。STUDIO: Free は独自ドメイン不可・STUDIO の表示あり。Mini 月590円(年払い)・1,290円(月払い)は2ページ+404、Personal 月1,190円(年払い)・1,720円(月払い)(https://studio.design/ja/pricing 。税込: ヘルプに「表示価格は全て税込み」https://help.studio.design/ja/articles/9317133 2026-10-02確認)。ペライチ: 常設の無料プランなし(1か月お試しのみ)、ライト 月1,628円(税込・月払い)〜、年契約は1割ほど安い(https://peraichi.com/pages/pricing )。Wix: 無料プランは独自ドメイン不可・Wix の広告あり。有料の金額は公式ページから読み取れず要確認(2025年の公式ブログでは月1,300〜13,500円、https://ja.wix.com/blog/2025/08/is-wix-free/ )。D は Instagram のプロフィールのリンクにサイトを入れ、サイトには Instagram へのボタンを置く(投稿をサイトに並べるかは S13)。
- **完成チェック例**: 「(A のとき)AI に『営業時間を10時〜18時に変えて』と頼み、数分後にスマホでサイトを開き直すと新しい時間が出ている」「(B のとき)更新画面にログインしてお知らせを1件書き、公開を押すと、数分以内にサイトのお知らせ欄の一番上に出る」「(D のとき)サイトの『最新のお知らせは Instagram で』を押すと、あなたの Instagram のページが開く」

## S3. どんなページを作るか(ページの組み立て)
- **重さ**: 聞く
- **当てはまる条件**: ②③
- **本人への聞き方**: 「伝えたいことは、スマホで上から下まで一気に読める量ですか? それとも料金表・実績・お知らせなど、あとから増えていくものがありますか?」
- **選択肢**:
  - A. 1枚のページ(LP) — 見え方: 上から順に「何をしているか→料金→お客様の声→問い合わせ」と読み進める / お金: 0円 / 注意: 内容が増えると長くなり、検索で個別の内容が見つかりにくい / 後から変える: ◎
  - B. 数ページに分ける(トップ・サービス・料金・紹介・問い合わせ) — 見え方: 上のメニューから見たいページを選ぶ / お金: 0円 / 注意: ページごとに文章が必要 / 後から変える: ◎
  - C. 数ページに分けて「お知らせ・ブログ」も付ける — 見え方: 記事が新しい順に並び、1記事が1ページになる / お金: 0円(自分で書くなら、自分で直す更新画面も要る) / 注意: 書き続けないと「最後の記事が2年前」のように見えてしまう / 後から変える: △
  - おまかせ → B。理由: 検索に出やすく、1枚にまとめ直すのもブログを足すのも簡単
- **AI向けメモ**: どの案でも作る: プライバシーポリシー(S7)、販売時の特定商取引法の表記(S11)、404。ページの一覧を youken.md の上半分に「## ページ一覧」として箇条書きで載せる。ブログは記事の URL(/blog/記事名)を最初に決める。後から変えるなら301転送が必要で、検索の評価を失いやすい。メニューや料金を載せるなら、値段は税込の総額で表示する(消費税法63条の総額表示義務、https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6902.htm )。値段は本人から受け取ったものだけを使い(AI が作らない)、決めたことリストに「値段は税込で表示」と書く。持ち帰りと店内で税率が違う店は、どう書くかを本人に1文で確かめる。2027-04-01〜2029-03-31 は飲食料品(今8%のもの)を1%に下げる案が出ている(国税庁リーフレット 2026-09、法案の成立が前提、https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/0026008-127_leaflet.pdf )。持ち帰りの値段を載せる店は、成立したら値段を直すことを「使い始めてから」の期限に書く。
- **完成チェック例**: 「スマホでメニューを開くと、全部のページに移動でき、どのページからもトップに戻れる」「(値段を載せるとき)メニューのページの値段がすべて『税込』で書かれ、あなたが渡した値段表と1つずつ同じになっている」

## S4. 雰囲気・見た目
- **重さ**: 聞く
- **当てはまる条件**: ②
- **本人への聞き方**: 「お客さんにどんな印象を持ってほしいですか? 3つの画面イメージから近いものを選んでください(色や写真はあとで変えられます)。お店のロゴや決まった色、Instagram、好きなサイトがあれば教えてください」
- **選択肢**:
  - A. やわらか・親しみやすい — 見え方: 丸みのある文字、明るい色、写真が大きめ / お金: 0円 / 注意: 高級感は出しにくい / 後から変える: ◎
  - B. きちんと・信頼できる — 見え方: 白地に紺やグレー、余白が多く、実績や数字が目立つ / お金: 0円 / 注意: 個性は出しにくい / 後から変える: ◎
  - C. 作品や写真が主役 — 見え方: 白か黒の背景に、写真や作品だけが大きく並ぶ / お金: 0円 / 注意: 文字が少ないので、何の仕事か伝わりにくいことがある / 後から変える: ◎
  - おまかせ → ロゴ・チラシ・お店の写真・Instagram の投稿があれば、その雰囲気にいちばん近い案を、その色で作る。なければ、飲食店・お店・教室は A、士業・会社・相談業は B、作品集は C。理由: 本人がすでに使っている雰囲気に合わせると、お客さんに同じお店だと分かりやすい
- **AI向けメモ**: HTMLを表示できる環境なら、question-style.md の「見本の出し方」に従って2〜3案を並べたHTMLを見せる。表示できなければ、テキストの画面イメージを選択式の道具の preview か文章で見せる。色だけでなく写真の大きさ・並び方の違いが分かるように作る。選ばれた見本は youken.md の「見本」に貼る。ロゴ・チラシ・名刺・Instagram の色を拾う。色・文字の大きさ・フォントは1か所(デザイントークン)で管理し、後から変える◎を保つ。日本語フォントは Noto Sans JP 等をサブセットで軽く。文字と背景のコントラストは WCAG AA 以上。有料テンプレートを使うならライセンスを確かめて記録。
- **完成チェック例**: 「スマホとパソコンの両方でトップを開くと、選んだ見本(○案)と同じ並び方と色で表示される」

## S5. お問い合わせの受け取り方
- **重さ**: 聞く
- **当てはまる条件**: ②④
- **本人への聞き方**: 「お客さんからの質問は、今どこに来ることが多いですか?(電話・Instagram の DM・LINE・メール)いちばん見落としにくいのはどれですか?」
- **選択肢**:
  - A. メールで届く — 見え方: 送信されると、あなたのメールに内容が届く。お客さんには「受け付けました」の自動返信 / お金: 0円 / 注意: 迷惑メールフォルダに入ることがあるので、最初にテストする / 後から変える: ◎
  - B. メールに届き、Googleスプレッドシート(表)にも1件1行で貯まる — 見え方: メールに加えて一覧表に残り、「対応済み」の印も付けられる / お金: 0円 / 注意: 表を見られる人を自分(とスタッフ)だけにする / 後から変える: ◎
  - C. フォームは作らない(電話・LINE・Instagram・メールのボタンだけ) — 見え方: 押すと電話・LINE・Instagram の DM・メールの画面が開く / お金: 0円 / 注意: メールアドレスをそのまま載せると迷惑メールが増えやすい / 後から変える: ◎
  - おまかせ → 本人がいちばん見ている所に集める。電話や DM で足りていて、予約は別にある(S6)なら C。それ以外は B。理由: 見落としにくい所に届けば、返事が遅れない
- **AI向けメモ**: 迷惑送信対策は聞かずに入れて記録する。第一候補 Cloudflare Turnstile(無料・チャレンジ数無制限・1アカウント20ウィジェット・1ウィジェット10ホスト名、https://developers.cloudflare.com/turnstile/plans/ )。reCAPTCHA は月1万回まで無料、10,001〜10万回は月$8 定額(https://docs.cloud.google.com/recaptcha/docs/compare-tiers )。どちらもトークンはサーバー側で検証する。honeypot 項目も併用。受け口の候補: Cloudflare Pages Functions/Workers でメール送信+シート追記 / Google Apps Script(Webアプリ)でシート追記+通知メール / Formspree(無料: 月50件・30日保存、有料 月$15≒2,400円(月払い)・$10(年払い)、https://formspree.io/plans 2026-10-02確認)。項目は最小限(名前・連絡先・内容)。フォームの直前に利用目的を明示し(個人情報保護法21条2項)、S7 へのリンクを置く。同意チェックは法律上の必須ではないが、確認のために置いてよい。健康・病歴などの要配慮個人情報を集める場合と、第三者に渡す場合は、本人の同意が法律上必要(20条2項・27条)。スプレッドシートは共有を本人(とスタッフ)だけにする。自動返信は迷惑メールの踏み台にならないよう、入力内容を全部は返さない。送信元ドメインの SPF/DKIM を設定。
- **完成チェック例**: 「スマホでフォームから自分あてにテスト送信すると、5分以内にメールの受信箱(迷惑メールフォルダではない)に届き、スプレッドシートにも1行増えている」「(B のとき。AI が確認・あなたの作業なし)ログアウトした状態と、別のテスト用 Google アカウントの両方でスプレッドシートの URL を開くと、中身は見えず『アクセス権が必要』と出る」

## S6. 予約やネット販売を付けるか
- **重さ**: 条件次第(S1 で「予約」を選んだ、またはサイトからお金を受け取る仕事なら聞く。販売は C7 と同じ判断なので、C7 の答えがあれば聞き直さない)
- **当てはまる条件**: ①③⑤
- **本人への聞き方**: 「予約(または注文)を、このサイトから受けられるようにしますか?」。事実の確認として「今、予約は1か月に何件くらいですか?(10件まで/10〜50件/50件より多い/わからない)」も添える(8問には数えないが、1回4問の枠には入る。依頼やステップ1で分かれば聞かない。A のお金の行を決めるのに使う)
- **選択肢**:
  - A. 予約サービスにつなぐ — 見え方: 「予約する」を押すと予約サービスの画面に移り(デザインはそのサービスのもの)、空いている日時を選ぶとその場で予約が終わる。確認メールも自動。同じ予約の入口を Instagram のプロフィールや Googleマップのお店の情報にも置ける / お金: 予約が月50件までは0円。超えると月9,790円〜(税込・1年契約。2026-10時点の目安) / 注意: 予約の記録はそのサービスに残り、ほかへ移すときは手作業になる / 後から変える: △

## S6b. 予約の決まり
- **重さ**: 条件次第(S6 で予約を付けると決めたら聞く。下の8つをまとめて1問として数える)
- **当てはまる条件**: ②⑤
- **本人への聞き方**: 「予約の決まりを、よくある形で仮に埋めました。違うところだけ番号で教えてください(例: 3は1〜6人)。全部このままでよければ『このまま(おまかせ)』で大丈夫です」
  1. 予約を受ける時間: 営業時間の中で30分ごと
  2. 1つの時間に予約で埋めてよい席: 全体の半分(残りは予約なしで来るお客さん用)
  3. 1組の人数: 1〜4人(5人以上はお電話で)
  4. 1組の利用時間: 90分
  5. 何日前まで: 前日の閉店まで(当日はお電話で)
  6. 予約の確定: 空いていればその場で確定(お店が確かめてから確定、にもできる)
  7. キャンセル: 確認メールから前日まで(当日はお電話で)
  8. 予約が入ったときの知らせ: あなたがいつも見ている所(メール・LINE・予約サービスのアプリのどれか)
- **選択肢**: 「このまま(おまかせ)」「要件書の確認のときに一緒に直す」の2つ。直す内容が決まっていれば、自動で付く「その他」に「3は1〜6人」のように番号と内容を書いてもらう(道具がなければ文章で)。8つの仮の値は質問文か preview に入れる。後者が選ばれたら、ステップ4で上半分を見せるときに8つの仮の値を番号付きで並べ、「直したい番号を教えてください」と聞く(「特に確かめてほしいこと」の3つの枠には数えない)
- **AI向けメモ**: 仮の値は仕事に合わせてから見せる(例: 教室・サロンなら 2 は「1つの時間に受ける人数」、4 は1回の時間。1対1の仕事なら 2・3 を外す)。決めたことリストには、直した番号を1つ1行で「あなた」、そのままの番号をまとめて1行(例: 予約の決まり: 30分ごと・席の半分・1〜4人・90分・前日まで・その場で確定・前日までキャンセル・メールで知らせ)で「おまかせ」と書く。選んだ予約サービスで各番号を設定できるかを、作る前に公式のヘルプで確かめる。できない番号は決めたことリストに「○○はできないので△△で代わりにする」と書く。知らせの届け方は catalog-web-app.md の W7 を参考にする。
- **完成チェック例**: 「(AI が確認・あなたの作業なし。テスト予約で)同じ時間に、予約で埋めてよい席数を超える人数で予約しようとすると『満席』と出て予約できない」「テスト予約を1件入れると、5分以内に決めた所(LINE など)に知らせが届く」

  - おまかせ → お店や事務所を構えているなら A、自宅で一人で仕事をしているなら B。理由: 決まりを守りながら自宅の住所を守れる
- **AI向けメモ**: 特定商取引法の通信販売(物の販売だけでなく役務=サービスの提供も含む)の広告表示: 販売価格(送料)、支払時期・方法、引渡し・提供時期、申込期間、申込みの撤回・解除(返品特約)、事業者の氏名(名称)・住所・電話番号、法人は代表者名など。消費者の請求で遅滞なく書面(ネット通販はメール可)を提供する旨を表示し、実際に遅滞なく提供できる措置があれば一部省略可(法11条ただし書。消費者庁 特商法ガイド https://www.no-trouble.caa.go.jp/what/mailorder/ )。ネット通販は最終確認画面にも、分量・価格(送料)・支払時期と方法・引渡し(提供)時期・申込期間・申込みの撤回や解除(返品特約)を表示する必要がある(法12条の6。返品特約の表示は法15条の3ただし書・省令44条も)。BASE 等を使えば申込画面はサービス側が対応するが、ショップ側の表記欄とサイト本体の表記をそろえる。事業ではない一回きりの不用品販売などは対象外になりうるが、判断が分かれるので要確認。
- **完成チェック例**: 「どのページでも一番下の『特定商取引法に基づく表記』を押すと開き、料金・支払い方法・キャンセルの決まりが、実際の申し込み画面と同じ内容になっている」

## S12. 自分専用のURL(ドメイン)とメールアドレス
- **重さ**: 聞く(C8 の代わり)
- **当てはまる条件**: ①③
- **本人への聞き方**: 「名刺やチラシに載せる URL は、お店や自分の名前が入ったもの(例: ○○.com)にしたいですか?」
- **選択肢**:
  - A. 無料の URL のまま — 見え方: 「○○.pages.dev」のような URL になる / お金: 0円 / 注意: あとで自分の URL に変えると、名刺や検索に出ていた URL が変わってしまう / 後から変える: △
  - B. 自分の URL を取る — 見え方: 「○○.com」「○○.jp」でサイトが開く / お金: 毎年の更新料で .com は年約1,700円、.jp は年約3,300円(税込。2026-10時点の目安) / 注意: 更新を忘れるとサイトが消え、他人に取られることもあるので自動更新にする / 後から変える: ◎
  - C. 自分の URL+同じ名前のメールアドレス(info@○○.com) — 見え方: そのアドレスでメールを送ったり受けたりできる / お金: 自分の URL の料金+1人あたり月880円(税込。Google の仕事用メール。1年契約)。受け取ってふだんの Gmail に転送するだけなら追加0円(2026-10時点の目安) / 注意: 転送だけの方法だと、そのアドレスから返事を出すのに一手間かかる / 後から変える: ◎
  - おまかせ → B。理由: 名刺やチラシに載せた後で変えると困るので、最初に取るのが安全。メールは困ってからでも足せる
- **AI向けメモ**: ドメインは本人名義・本人のアカウント・本人のカードで取る(AI や制作者の名義にしない。解約・引き継ぎトラブルの元)。会社やお店のサイトを社員・スタッフが作るなら会社の名義にし、担当が変わっても使える会社の共有メールアドレスと会社のカードで登録して、ログインできる人を2人にする(ビジネスプロフィール・Search Console・解析・予約・ネットショップのアカウントも同じ)。名義は下半分「外部サービスと料金の前提」に、更新の確認は「使い始めてから」の「年に1回やること」に書く。本人向けの金額は C8 と同じ出典にそろえる: ムームードメインの更新料金 .com 1,728円・.jp 3,344円・.co.jp 4,378円/年(税込・サービス維持調整費込み、https://muumuu-domain.com/domain/price 2026-10-02確認)。ほかの例: エックスサーバードメイン 更新料 .com 1,721円・.jp 3,102円・.co.jp 4,136円/年(税込、https://www.xdomain.ne.jp/domain/price.php 2026-10-02確認)。初年度の安さでなく更新料で比べる。.co.jp は日本で登記した会社だけが取れる。Cloudflare Registrar は上乗せなしの原価だが .jp は扱っていない(https://www.cloudflare.com/products/registrar/ )。受信だけなら Cloudflare Email Routing(無料・受信を転送、https://developers.cloudflare.com/email-routing/ )。送信もするなら Google Workspace Business Starter 月800円/人(税抜・年間プラン。税込880円。最初の3か月の割引表示あり、https://workspace.google.com/intl/ja/pricing.html 2026-10-02確認)。SPF・DKIM・DMARC を設定。無料 URL は Cloudflare Pages の *.pages.dev。
- **完成チェック例**: 「スマホのブラウザに『○○.com』と入れるとお店のページが開き、アドレス欄の近くに『保護されていない通信』『安全ではありません』と出ない」「別のアドレスから info@○○.com にメールを送ると、いつもの受信箱に届く」

## S13. 地図・SNSの埋め込み
- **重さ**: 条件次第(地図とリンクは聞かずに入れる。本人が Instagram などでお知らせを出しているなら「最新の投稿をサイトにも並べるか」を聞く。出していなければ AI が A に決めて記録)
- **当てはまる条件**: ②
- **本人への聞き方**: (載せる先は事実の確認として聞く)「サイトに載せたい SNS のアカウント(Instagram・LINE など)はありますか?」。お知らせを出しているなら「Instagram の最新の投稿を、サイトにも並べますか?」
- **選択肢**:
  - A. リンクだけ — 見え方: SNS のアイコンを押すと、あなたのアカウントのページが開く / お金: 0円 / 注意: サイトだけを見る人には、最新のお知らせが見えない / 後から変える: ◎
  - B. サイトにも最新の投稿を並べる — 見え方: トップに最新の投稿の写真が数件並び、押すと Instagram が開く / お金: 0円 / 注意: Instagram 側の仕組みが変わると、表示が止まることがある / 後から変える: ◎
  - おまかせ → お知らせを Instagram に出していて、S2 が D なら B。それ以外は A。理由: いつものお知らせがサイトでも見え、二重に書かずに済む
- **AI向けメモ**: 地図は Google マップの「地図を埋め込む」(iframe)。Maps Embed API も無料・回数無制限だが API キーが必要(https://developers.google.com/maps/documentation/embed/usage-and-billing )。地図は遅延読み込みにする。B は Instagram のプロアカウント(ビジネスかクリエイター。切り替えは無料)と Meta の連携が要る(https://developers.facebook.com/docs/instagram-platform/overview/ )。アクセストークンには期限があり、自動で更新する仕組みが要る。作る時点で要確認。投稿の一覧は Worker でまとめて取得して1時間ほどキャッシュし、画像を軽くする(ビルドのたびに取ると Pages Free の月500ビルドを超えやすい)。決めたことリストに「SNS はリンクのみ」または「最新の投稿を○件表示」と書く。埋め込んだものは外部送信の一覧(S7・S9)に載せる。
- **完成チェック例**: 「スマホでアクセスのページの地図を押すと、Googleマップでお店の場所が開く」「SNS のアイコンを押すと、あなたのアカウントのページが開く」「(B のとき)Instagram に投稿して1時間後にサイトを開くと、その投稿がいちばん左(上)に出ている」
