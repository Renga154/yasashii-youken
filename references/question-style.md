# 聞き方ガイド

## 答えられる質問にする

本人はコードが書けないので、技術の選択肢を並べられても判断できない。代わりに、本人が知っている事実(使う人、頻度、困ること、お金)を聞き、技術の判断はAIが答えから導く。

| 聞かない(技術の質問) | 聞く(本人の世界の質問) |
|---|---|
| ログイン機能を付けますか? | 他の人に見られたら困る内容ですか? あなた以外に使う人はいますか? |
| データベースは何を使いますか? | スマホを買い替えたり、別のパソコンから開いたりしても、記録は残っていてほしいですか? |
| レスポンシブ対応は必要ですか? | 主にスマホで見ますか、パソコンで見ますか? |
| 決済は Stripe と PAY.JP のどちらにしますか? | お客さんからお金を受け取りますか? 1回いくらくらいで、月に何件くらいですか? |
| 定期実行は cron にしますか? | これは毎朝など決まった時間に動いてほしいですか、それともボタンを押したときだけですか? |

使える言い方:
- 「もし〜になったら困りますか?」(セキュリティ、データ消失、他人に見られる)
- 「1日(1か月)に何回くらい/何人くらい?」(規模、料金)
- 「今はどうやっていますか?」(仕事のルール、置き換える対象)
- 「A と B、どちらがイメージに近いですか?」(見た目、使い心地。見本付きで)

フレームワーク、プログラミング言語、ライブラリ、ファイル構成などの「作り方」の判断は聞かない。AIが決めて、要件書の下半分「構成」に書く(決めたことリストには載せない)。

## 選択肢カード

1つの質問は、次の形で書く。

```
Q1. 家族と一緒に使いますか?
(なぜ聞くか: 一緒に使うなら「本人だけが開ける仕組み(ログイン)」と「誰が何を見られるか」の設定が要り、作る手間が少し増えます)

A. 自分だけで使う
   見え方: スマホで開くとすぐ記録画面。ログインなし
   お金: 0円
   注意: このスマホの中だけに保存するので、機種変更やブラウザの掃除で記録が消えることがある(iPhone の Safari では、7日間開かないと消えることもある)
   後から変える: △ 家族で使いたくなったら一部作り直し
B. 家族で共有する(おすすめ)
   見え方: 最初に1回ログイン。招待した家族だけが、同じ記録を見て書ける
   お金: 0円(2人で使う量なら無料の範囲。2026年10月時点の目安)
   注意: 家族のスマホでも1回ずつログインが要る
   後から変える: ◎ 一人用に戻すのは簡単
C. おまかせ(おすすめの B で進めます。記録が消えにくく、後から一人用に戻すのも簡単なため)
```

カードの各行:
- **見え方**: 本人や使う人の画面で何が起きるか。動作の言葉で書く
- **お金**: 税込の円で。月払いと年払いで違うなら「年払いなら月○円、月払いなら月○円」。1年契約なら「1年契約」と書く。「〜」は使う量で変わるときだけ使う。無料の範囲があるなら「〜までは無料」。売上に比例する手数料は「1万円売れると約○円」の形で。税抜しか分からないときは「税抜」と書く
- **注意**: その選択で起こりうる困りごと。1つに絞る
- **後から変える**: この案を選んだあと、ほかの案に変えるときの大変さ。◎ 簡単 / △ 一部作り直し / × ほぼ作り直し。変える先によって違うときは、いちばん大変な方を記号にして言葉を添える(例: × ストアのアプリにするなら作り直し)

おすすめは本人の答えに合わせて1つに決める。一覧の「おまかせ →」に条件が付いていても(「自分用なら A、お客さん向けなら B」など)、本人に見せる前に1つに決める。迷う場合は後から変えやすい方をすすめる。おすすめの案の末尾に「(おすすめ)」を付け、おまかせの行で理由を一言添える。

## 本人に見せるときの注意

- カードのどの行(見え方・お金・注意・後から変える・preview)にも、本人が知らないサービス名(microCMS、Supabase など)は出さない。「更新画面の無料サービス」のように役目で書き、名前は要件書の下半分に書く。
- 一覧の選択肢にある「(S6)」「(A4)」「上限は C3」「(I2 の D)」などの番号は AI 用の参照なので、本人に見せるときは消すか中身の言葉にする(例:「上限は C3」→「上限は最初に決めた毎月の金額」)。
- 「C にするなら」のように別の案を記号で指す部分は、案の名前に置き換える(選択式の道具では A・B・C が表示されないため。例:「△ C にするなら一部作り直し」→「△ 終わったら知らせる形にするなら一部作り直し」)。

## 選択式の道具を使うとき

Claude Code の AskUserQuestion の場合(ほかの道具も、その上限に合わせて同じ考え方で):

- question: 「Q1. 家族と一緒に使いますか?」+ なぜ聞くかを一文。1回に4問まで。答えが別の質問の前提になるものは次の回に回す
- header: 12文字以内の見出し(例: 使う人)
- options: 2〜4個。最後の1つは「おまかせ(○で進めます)」にするので、実際の案は3つまで。一覧に4案以上あるときは、それまでの答えから一番遠い案を外し、質問文の最後に「ほかに『○○』もできます。選びたいときは『その他』に書いてください」と一言書く。自分で「その他」は足さない
- label: 短く。おすすめの案の末尾に「(おすすめ)」
- description: 「見え方。お金。注意。」を1〜2文で。「注意」を落とさない
- preview: 各案のカード4行(見え方/お金/注意/後から変える)を入れる。見た目の質問では、テキストの画面イメージとお金・後から変えるの2行を入れる。おまかせの preview には、おすすめの案と同じ行と、おすすめの理由を一文入れる
- multiSelect は使わない(preview は1つだけ選ぶ質問でしか出ない)
- 2回目以降の回では、質問の前のメッセージに「全部おまかせでよければ、どの質問も最後の『おまかせ』を選んでください」と一言添える。「残りは全部おまかせでいいですか?」という質問は同じ回に入れない(同じ回の質問には全部答えてから送るので、答えが食い違う)
- 「よくある形で仮に埋めました」の1問(本人のルールをまとめて確かめる形)は、選択肢を「このまま(おまかせ)」「要件書の確認のときに一緒に直す」の2つにし、仮の値は質問文か preview に番号付きで書く。直す内容が決まっていれば、「その他」に「3は1〜6人」のように書いてもらう

道具がない環境では、選択肢カードを番号付きの文章で並べ、最後に「1-A、2-おまかせ のように答えてください」と書く。

## 「よくわからない」と言われたとき

- 基本はおまかせとして進め、決めた人を「おまかせ(よくわからない)」と記録する。ステップ4の「特に確かめてほしいこと」の候補にする
- お金か個人情報に当たる質問だけは、本人の生活の例を1つ足して1回だけ言い換える(例:「この家計簿の中身が、会社の人に見られたら困りますか?」)。それでも分からなければおまかせにする
- 1つの回で2問以上出たら、お金・個人情報の質問の言い換えだけを次の回の先頭で聞き(言い換えは8問に数えないが、1回4問の枠には入る)、それ以外の質問と、まだ聞いていない質問は AI が決めて記録し、ステップ4の確認で拾う。次の回がもうなければ、言い換えもステップ4の確認に回す

## 見本の出し方

見た目、使い心地、届くものの形は、言葉で説明するより見本で見せる。

テキストで描く場合(15行以内、主要な要素だけ):

```
┌──────────────────┐
│ 今月の支出  ¥48,200 │
│ ──────────────── │
│ 10/1 食費   ¥1,200 │
│ 10/1 交通   ¥  420 │
│ 9/30 日用品 ¥  980 │
│                  │
│   [ + 記録する ]    │
└──────────────────┘
```

届くもの(LINE やメール)は、実際に届く文面の見本を、何件・何行・何時・送り主の名前まで入れて書く。

HTMLを表示できる環境では、2〜3案を並べたHTMLを1枚作り、「どれがイメージに近いですか?」と聞いてもよい。色や雰囲気だけでなく、画面の並び方や操作の流れの違いが分かるように作る。選ばれた見本は要件書の「見本」の欄に貼る。

## 言い換え表

| 専門用語 | やさしい言い方 |
|---|---|
| ログイン/認証 | 本人だけが開けるようにする仕組み |
| 権限 | 誰が何を見られる・変えられるか |
| データベース | 情報をしまっておく場所 |
| サーバー/ホスティング | アプリを置いておくインターネット上の場所 |
| デプロイ/公開 | インターネットで見られるようにすること |
| URL | ページの住所(例: ○○.com) |
| ドメイン | 自分専用のページの住所 |
| API | 他のサービスとつなぐ窓口 |
| APIキー/環境変数 | サービスを使うための合言葉(人に見せてはいけない) |
| シークレット/スクリプトプロパティ | 合言葉をしまう、画面に出ない場所 |
| ローカル保存 | その端末の中だけに保存 |
| クラウド保存 | インターネット上に保存(どの端末からでも見られる) |
| バックアップ | 予備のコピー |
| レスポンシブ | スマホでもパソコンでも見やすい |
| CMS/管理画面 | 文章や写真を自分で更新できる画面 |
| ノーコードのサービス | 画面を見ながら自分でページを組み立てるサービス |
| LP | 1枚で完結する宣伝のページ |
| 定期実行(cron)/トリガー | 決まった時間に自動で動かす目覚まし |
| スクレイピング | 他のサイトから情報を自動で読み取る |
| RSS | ニュースサイトなどが配っている新着記事の一覧 |
| Webhook | 何か起きたときに自動で知らせが届く仕組み |
| PWA | ホーム画面に置けるWebアプリ |
| LINE公式アカウント | お知らせを送れるお店・会社向けのLINEアカウント(個人のLINEとは別) |
| モデル | AIの種類 |
| トークン | AIが読み書きする文字の量(料金の単位) |
| 無料枠 | 一定の量までは無料で使える範囲 |

| ドラッグ | 指(マウス)で押したまま動かす |

一覧にない用語も、使う前に「この言葉なしで言えないか」を考える。

## 避けること

- 1つの質問に2つ以上の決めごとを混ぜる(本人のルールをまとめて確かめるときは、「よくある形で仮に埋めました。違うところだけ番号で教えてください」の形にする)
- 調べれば分かることを聞く(料金、規約、プロジェクトの中身)
- 技術名から始める(「Supabase と Firebase、どちらにしますか?」)
- 全部の選択肢を同じ重さで並べて、おすすめを言わない
- 「必要ですか?」とだけ聞く(ほとんどの人は「はい」と答える。代わりに、ない場合に何が困るかを示す)
