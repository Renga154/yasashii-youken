# 決めること一覧: 共通(どの種類でも最初に見る)

どんなものを作るときも、種類ごとの一覧(catalog-web-app.md など)より先にこのファイルを見る。「重さ: 聞く」は候補で、全部は聞かない。絞り方は SKILL.md のステップ2に従い、同じ順位なら上にあるものを残す。ステップ1(ひとこと確認)の答えで決まった項目は聞き直さず、決めたことリストに記録だけする。種類別の一覧と重なる項目は、その一覧の冒頭に書いた扱いに従う(例: ホームページでは C1・C8・C9 の代わりに S2・S6・S12、自動化では C1 の代わりに A1 で聞く)。
「当てはまる条件」の番号は SKILL.md の5条件: ①お金・抜けにくさ ②使う人が見るもの・できること ③後から変えにくい ④個人情報・セキュリティ ⑤本人の仕事や生活のルール。

## C1. 作らずに、今あるサービスで済まないか
- **重さ**: 条件次第(依頼の中心が次のどれかなら聞く: ネットショップ・予約受付・申し込みフォーム / 教室・お店・団体の名簿と月謝・会費・出欠の管理 / お客さんの質問に資料をもとに自動で答えるチャット。それ以外は AI が「作る」と決めて記録。ホームページは catalog-website の S2・S6、決まった作業の自動化は catalog-automation の A1 で聞き、ここは使わない)
- **当てはまる条件**: ①③
- **本人への聞き方**: 「同じようなことができる既製のサービスがあります。そのまま使う、一部だけ使う、自分のやり方に合わせて作る、のどれがイメージに近いですか?(既製のサービスを使って困ったことがあれば教えてください)」
- **選択肢**:

  - B. 全部を自分用に作る — 見え方: 画面も手順も自分のやり方に合わせられる / お金: 置き場所代 0円〜月数千円(使う量と、お金を受け取るかで変わる) / 注意: 壊れたときの直しや更新は、自分と AI で行う / 後から変える: △(既製のサービスに移るときは記録の移し替えが要る)
  - C. 既製のサービスで始めて、足りなくなったら作る — 見え方: 最初は A と同じ。困りごとがはっきりしてから作るので、作る範囲が小さく済む / お金: A と同じ / 注意: 作るときに記録の移し替えが要る / 後から変える: △
  - D. ページ(画面)は AI が作り、予約・支払い・フォームなどの部品だけ既製のサービスをつなぐ — 見え方: お店のページはあなたの好みに合わせて作り、「予約する」などを押すとそのサービスの画面に移る / お金: ページの置き場所0円+部品のサービスの料金(無料の範囲があるものが多い。メモの候補から書く) / 注意: 予約や支払いの記録はそのサービスの中に残り、見るのもそのサービスの管理画面 / 後から変える: △(部品のサービスを替えるときは記録の移し替えが要る。ページはそのまま)
  - おまかせ → 見せるページと、既製で足りる部品(予約・販売・フォーム)の組み合わせなら D。既製で足り、本人が自分で操作できるなら C。本人独自のルールや手順が中心なら B。ステップ1で設定の作業は「一緒に見ながら」と答えたら、画面やページを本人が自分で組み立てる既製のサービスをおまかせ先にしない
- **AI向けメモ**:

  - B や D に決めても、支払い・予約通知などの部品は既製サービス(Stripe など)とつなぐ方が安全で早い。「既製のサービスとも比べたうえで作ることにした」を決めたことリストに残す。

## C2. 使う人と公開範囲
- **重さ**: 聞く(ステップ1の「誰が使う?」で答えが出ていれば聞かずに記録)
- **当てはまる条件**: ②③④
- **本人への聞き方**: 「これを開いて使うのは誰ですか? いずれ一緒に使いそうな人も含めて、いちばん近いものを選んでください」
- **選択肢**:
  - A. 自分だけ — 見え方: 開くとすぐ使える。記録をこの端末だけに置くなら、本人だけが開ける仕組み(ログイン)もなし / お金: 0円で収まることが多い / 注意: 後から誰かと一緒に使いたくなると、仕組みの追加が要る / 後から変える: △
  - B. 家族・仲間(顔がわかる数人〜数十人) — 見え方: 最初に1回ログイン。招待した人だけが使える / お金: 0円(この人数なら無料の範囲に収まることが多い) / 注意: 誰が何を見られる・変えられるかを決める必要がある / 後から変える: △(自分だけに戻すのは簡単。お客さん向けにするなら申し込みの画面を足す)
  - C. お客さん(知らない人も使うが、使い道は決まっている) — 見え方: お客さんは申し込みや予約の画面だけ、あなたは管理用の画面も使う / お金: 0円〜月数千円 / 注意: お客さんの名前や連絡先を預かることが多い(C6)。無料の置き場所の中には、仕事での利用を禁じているものがある / 後から変える: △
  - D. 誰でも(ネットで見つけた人が見られる) — 見え方: URL を知っていれば誰でも見られ、検索にも出る / お金: 0円(見る人が急に増えると有料になることがある) / 注意: 書き込みができるなら、いたずらや迷惑な書き込みへの備えが要る / 後から変える: △(一部の人だけに閉じるなら、ログインの仕組みを足す)
  - おまかせ → ステップ1の答えに一番近いもの。「いずれ」「〜かも」の人は今回はログインの仕組みに入れず、記録をその人ごと(例: 生徒・家族ごと)に分けておくだけにして、決めたことリストに「○○さんが見る仕組みは今回は作らない(足すときは一部作り直し)」と書き、ステップ4で確かめる。迷うときは B(閉じた形で始めて広げる方が、広く出してから閉じるより安全なため)
- **AI向けメモ**: 画面ごとに違ってよい(例: お店の紹介は D、予約の管理は自分だけ)。その場合は聞かずに画面ごとに決め、決めたことリストに1行ずつ書く。A=ログインなし・端末内保存か一人用アカウント。B=招待制ログイン(メールのリンクなど)+データごとのアクセス制御。C=公開フォーム+管理画面の2面構成で、管理側には認証を付ける。D=静的配信。書き込みがあるならスパム対策(Cloudflare Turnstile など)と削除手段。「URL を知らなければ見られない」は守りにならない(転送・推測される)と記録する。C・D を仕事に使うなら Vercel Hobby は使えない(C7 メモ)。利用者同士がメッセージや投稿でやり取りできる仕組みは、電気通信事業の届出や外部送信規律(C6 メモ)の対象になりうる → 要確認。本人が会社員で「同僚にも」と言ったら、会社のルール(個人で作った仕組みや外部のサービスを仕事に使ってよいか)を本人のルール(⑤)として1問で確かめるか、「あなたにやってもらうこと」に入れる。
- **完成チェック例**: 「(B の場合。AI が確認・あなたの作業なし)招待していないテスト用のメールアドレスでログインしようとすると、中身は見えず『招待された人だけが使えます』と出る」

## C3. お金の上限(毎月いくらまで払えるか)
- **重さ**: 聞く(最初の回で1回だけ聞き、以後の回のカードはこの範囲で組み立てる。二度は聞かない。AI の見積もりで、おすすめの形が毎月0円に収まり、仕事やお店(会社・教室・個人事業など)で使うものでもなければ、聞かずに「毎月0円の範囲で作る」と記録する)
- **当てはまる条件**: ①
- **本人への聞き方**: 先に AI がこの依頼の見込み額を2案出してから聞く。「この内容だと、A案は月0円(○○の無料の範囲で動かすため)、B案は月約○円(○○のため)です。毎月いくらまでにしますか?(自分専用の URL 代のような年に1回のお金は、別に示します)」。見込みを出せないときだけ「これを使い続けるのに、毎月いくらまでなら払ってもいいですか?」と聞き、B を「月1,000円くらいまで」、C を「月5,000円くらいまで」にする
- **選択肢**:
  - A. 0円(A案。無料の範囲だけ) — 見え方: 無料の範囲で作る。使う量が増えると止まったり遅くなったりすることがある / お金: 0円 / 注意: 無料の範囲には、仕事での利用が禁止だったり、しばらく使わないと止まったりするものがある / 後から変える: ◎
  - B. 月約○円まで(B案) — 見え方: B案の有料プランで作る。止まりにくく、使える量も増える / お金: 月約○円まで / 注意: ドル払いのサービスは円安で少し上がることがある / 後から変える: ◎
  - C. 金額より、ちゃんと動くことを優先 — 見え方: 作りながら AI が「この使い方なら月○円くらい」と見積もり、B案を超えそうなら作る前に相談する / お金: 見積もり次第(決めた上限は要件書の「お金」に書く) / 注意: 使った分だけ払うサービスは、上限を決めないと高くなることがある / 後から変える: ◎
  - おまかせ → A で始め、超えそうなら作る前に相談(後から有料プランに上げるのは簡単だが、払い始めたものをやめるのは手間なため)。仕事やお店で使うものでも、仕事に使ってよい無料の置き場所(C7・C8 メモ。Vercel Hobby は使わない)と、無料で毎日取れる予備のコピー(C10)で足りるなら A。足りない理由(使う人が数百人を超える、止まると仕事が止まる など)を具体的に1つ言えるときだけ B をすすめ、その理由をおまかせの行に書く
- **AI向けメモ**: 答えを youken.md の「お金」の「上限」に書き、以後のカードの「お金」をこの上限で絞る。どのカードにも上限に収まる案を1つ以上入れる(0円なら0円の案。0円では作れない機能なら、そう書いて「やらないこと」に回すか、「上限を超えます」と明記した案として出す)。C3 と同じ回のカードは答えの前に作るので、0円の案を1つ入れておき、上限を超える案が選ばれたらステップ4の「特に確かめてほしいこと」で確かめる。種類別の一覧の予算の項目(W11 のお金の部分・A9・I3 の金額)はこの答えを使い、聞き直さない。お金を払うことを決める人がほかにいる(ステップ1)なら、「○○さんに確かめる前提の仮の上限」として聞く。「よくわからない」でも、0円で作れない依頼なら0円に決めず、いちばん安い案を仮の上限にしてステップ4で確かめる(ほかに決める人がいれば「お金」に「○○さんの確認待ち」と書く)。従量課金(AI の API、メール・SMS 送信など)を使うなら、サービス側の利用上限・予算アラートを設定し、決めたことリストに「月○円を超えたら止まる」と書く。売上に比例する手数料は月額と分けて書く(例: 1万円売れると約360円)。ドル建ては「約」を付け、為替の前提を下半分の「外部サービスと料金の前提」に書く。
- **完成チェック例**: 「要件書の『お金』の毎月の合計が、決めた上限以下になっている。使った分だけ払うサービスがあれば、その管理画面に『○円を超えたら止める』設定が入っているのを一緒に画面で見る」

## C4. 記録をどこに残すか
- **重さ**: 条件次第(入力したものや記録を後で見返すものなら聞く。見るだけのページ、記録を既製のサービスに預けるだけなら AI が決めて記録)
- **当てはまる条件**: ③④
- **本人への聞き方**: 「スマホを買い替えたり、別のパソコンから開いたりしても、記録は残っていてほしいですか?」
- **選択肢**:
  - A. この端末の中だけ — 見え方: ログインなしですぐ使える。ほかの端末からは見えない / お金: 0円 / 注意: 機種変更や、ブラウザの履歴・データの削除で消えることがある。iPhone の Safari では、7日間そのページを開かないと自動で消えることがある(ホーム画面に追加して使えば避けられる) / 後から変える: △(ほかの形に替えるときは、記録の移し替えと一部作り直しが要る)
  - B. インターネット上の保存場所 — 見え方: どの端末から開いても同じ記録。最初にログインが要る / お金: 0円〜(無料の範囲に収まることが多い。上限は C3) / 注意: 無料の範囲では、1週間だれも開かないと止まるものがある(止まったら管理画面で[再開]を押す。手順は要件書に書く。AI はなるべく止まらない保存先を選ぶ) / 後から変える: △(同上)
  - C. 自分の Google スプレッドシート — 見え方: いつものスプレッドシートで、中身を見たり直したりできる / お金: 0円(Google の無料の保存容量15GBの中。Gmail や写真と同じ15GBを分け合う) / 注意: 件数が多くなったり、たくさんの人が同時に使ったりすると遅くなる / 後から変える: △(同上)
  - おまかせ → 消えたら困る記録なら B、自分だけで Google をよく使うなら C、試しに使うだけなら A
- **AI向けメモ**:
  - A=localStorage / IndexedDB。書き出し・読み込みボタンを付ける。Safari は、7日間操作のないサイトのスクリプトが保存したデータ(localStorage・IndexedDB など)を消す。ホーム画面に追加した Web アプリは実際に使った日で数えるので、使っていれば消えない(https://webkit.org/blog/10218/ 2026-10-02 確認)。A を選ぶなら W4 の B(ホーム画面に追加)と書き出しボタンをセットにする。
  - B=Supabase / Firebase など。Supabase Free は1プロジェクト500MB・月5万人まで・動かせるプロジェクト2つ・1週間アクセスがないと一時停止・自動バックアップなし。Pro は月25ドル〜(約4,000円)で7日分のバックアップ(https://supabase.com/pricing , https://supabase.com/docs/guides/platform/backups 2026-10-02 確認)。自分だけ・家族だけの記録で1週間使わない日がありそうなら、止まらない保存先を優先する(Firebase の無料プラン Spark: Firestore 1GiB・1日5万回の読み取り・2万回の書き込み。料金ページに、使わないと止まる決まりはない。https://firebase.google.com/pricing 2026-10-02 確認。または C)。Supabase を使うなら、決めたことリストに「1週間だれも開かないと止まる」と本人の言葉で書き、再開の手順を「運用の手順」と「使い始めてから」の「止まったとき・困ったとき」に書く。

- **完成チェック例**: 「(B の場合)スマホで1件記録してから、パソコンで同じ URL を開いてログインすると、同じ記録が見える」

  - おまかせ → よく変わる場所(値段・営業時間・お知らせ、届く時間やジャンルなど)だけ自分で変えられるようにする(B の一部)。理由: 全部を更新画面にすると、作る量が大きく増えるため。ステップ1で設定の作業は「一緒に見ながら」と答えていたら A
- **AI向けメモ**: B は CMS・管理画面のほか、Google スプレッドシートを更新画面にして読み込む方法が簡単(自動化の設定も「設定」シートにすると本人が直しやすい)。運用に要るアカウント(置き場所・ドメイン・支払い・記録の保存先・AI会社)はすべて本人名義で作り(会社や、スタッフのいるお店の仕事なら会社の名義: 担当が変わっても使える会社の共有メールアドレスと会社のカードで登録し、ログインできる人を2人にする)、「あなたにやってもらうこと」に入れ、名義を下半分の「外部サービスと料金の前提」に書く。ログイン情報は本人が保管する(AI はパスワードを預からない)。youken.md の「使い始めてから」に「更新のしかた」「止まったとき・困ったとき」「年に1回やること(ドメイン更新・無料の範囲の確認・部品の更新)」を書く。
- **完成チェック例**: 「(B の場合)更新画面で値段を変えて保存し、お客さん側のページを開き直すと、新しい値段が表示される」

## C10. データが消えたときの備え
- **重さ**: 条件次第(記録が残るもので、消えたら困るなら聞く。見るだけのページなら AI が決めて記録)
- **当てはまる条件**: ③④

## C11. スマホとパソコンのどちら中心か
- **重さ**: 条件次第(ステップ1の「あなた自身は?」と完成のイメージで分からないときだけ聞く。分かれば AI が決めて記録)
- **当てはまる条件**: ②
- **本人への聞き方**: 「主にスマホで使いますか、パソコンで使いますか? お客さんなど、ほかの人はどちらで開きそうですか?」
- **選択肢**:

  - B. パソコン中心 — 見え方: 横に広い表や、たくさんの情報を一度に見られる画面。スマホでは見るだけ程度 / お金: 0円 / 注意: スマホでの入力はしにくい / 後から変える: △
  - C. 両方同じくらい — 見え方: 同じ画面が、スマホでは縦に、パソコンでは横に並ぶ / お金: 0円 / 注意: 作る量と確かめる量が少し増える / 後から変える: ◎

- **完成チェック例**: 「スマホを縦向きにしても横向きにしても、ボタンや文字が画面からはみ出さず、横にずらさなくても全部読める」

## C12. 作る期限と、まず最小版でよいか
- **重さ**: 条件次第(期限の話が出たとき、または「できること」が4つ以上になりそうなときだけ聞く。それ以外は AI が A に決めて記録)

- **AI向けメモ**: youken.md の「できること」は最小版の範囲だけにし、残りは「やらないこと」に理由付きで書く。期限(開店日・イベント日など)があれば「使い始めてから」の「期限」に書き、その日より前に完成チェックを終える。最小版でも、後から変えにくい判断(C4 記録の場所、C5 守り、C6 個人情報、C7 支払い)は最初から本番のつもりで決める。
